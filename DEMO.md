# cortex-cc · Demo Script

Step-by-step walkthrough for a hiring-manager demo. Total runtime: ~10 minutes.

---

## Prerequisites

- Docker + Docker Compose installed
- 8 GB free RAM (Llama 3.1:8b needs ~5 GB)
- Ports 8080, 11434, 8001, 5001 free

---

## 1. Start all services

```bash
make docker-up
make docker-pull-model    # one-time — downloads Llama 3.1:8b (~4.7 GB)
```

Services starting:

| Container    | Role                          | Port  |
|--------------|-------------------------------|-------|
| ollama       | Local LLM runtime             | 11434 |
| sentiment    | DistilBERT sentiment scoring  | 5001  |
| whisper      | OpenAI Whisper STT            | 8001  |
| cortex-cc    | Go API + supervisor dashboard | 8080  |

Wait until all four containers show `healthy`:

```bash
docker compose ps
```

---

## 2. Open the dashboard

Navigate to **http://localhost:8080** in your browser.

You should see:

- Green "Live" indicator (top right) — WebSocket connected
- Stats row: Active Calls, In Queue, Available Agents, SLA Breaches
- Live Call Queue table (auto-populated in ~5s as the engine seeds calls)
- Agents panel on the right
- Agent Assist panel (below queue)
- AI Copilot chat (bottom)

---

## 3. Watch the engine run (30 seconds)

The engine auto-generates:
- Calls entering queues (Sales, Billing, Support)
- Calls being answered by agents
- Simulated transcript lines every 5 seconds
- Sentiment scores updating in real time (green bar = positive, red = negative)
- SLA breach alerts after calls wait >90s

**Point out:** The sentiment bar in the call table — negative sentiment (red) triggers an alert automatically.

---

## 4. Agent Assist in action

After 30–60 seconds you should see suggestion cards appear in the **Agent Assist** panel.

Each card shows:
- The call ID + queue
- What the customer said (the trigger)
- The suggested agent response (generated by Llama 3.1:8b on-prem)

**Say:** "Every time a customer speaks on an active call, Llama 3.1:8b reads the last 6 transcript lines and generates a response suggestion for the agent — completely on-prem, no data leaves the building."

---

## 5. AI Copilot chat — 3 demo queries

Type these into the AI Copilot box:

### Query 1 — fleet overview
```
Which agents are currently busy and what queues have the highest wait times?
```

The copilot calls `get_queue_status` and `get_agent_states` internally, then summarises the result.

### Query 2 — flag a call
```
Flag call C-001 — customer sounds very upset
```

The copilot calls `flag_call` and confirms the action.

### Query 3 — proactive advice
```
Should I be worried about anything right now?
```

The copilot calls `get_sentiment_report` and `get_queue_status`, then gives a multi-point advisory.

## 6. Whisper transcription (optional)

If the Whisper container is healthy, upload an audio file:

```bash
curl -X POST http://localhost:8080/api/transcribe \
  -F "audio=@sample.wav" \
  -F "call_id=C-001" \
  -F "speaker=customer"
```

Response:
```json
{
  "call_id": "C-001",
  "segments_stored": 4,
  "language": "en",
  "duration": 12.4,
  "elapsed": 1.8
}
```

Transcript segments are stored in SQLite and returned by `get_call_transcript`.

---

## 7. Proactive monitor (wait 60s)

The monitor polls every 60 seconds and automatically broadcasts:

- `warn` alert if ≥1 call breaches SLA
- `critical` alert if ≥3 SLA breaches
- Queue overload alert if ≥5 calls waiting
- Negative sentiment spike if average score < -0.4
- Agent shortage if ≤10% of agents are available

Each alert is accompanied by an **AI advisory** — a violet banner with a concrete recommendation generated by Llama 3.1:8b.

## 8. REST API tour

```bash
# Live queue status
curl http://localhost:8080/api/queue-status

# All agent states
curl http://localhost:8080/api/agents

# Transcript for a specific call
curl http://localhost:8080/api/calls/C-001/transcript

# Sentiment report
curl http://localhost:8080/api/sentiment-report

# Copilot chat (direct)
curl -X POST http://localhost:8080/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"How many agents are on break right now?"}'

# Reset conversation history
curl -X POST http://localhost:8080/api/chat/reset
```

## 9. Architecture talking points

**Why on-prem?**
Contact centers handle PII (names, account numbers, call recordings). Sending that data to a cloud AI breaks GDPR, HIPAA, and most enterprise security policies. Every AI component in cortex-cc runs inside the customer's own network:

| Component       | Technology              | Why chosen                              |
|-----------------|-------------------------|-----------------------------------------|
| LLM             | Ollama + Llama 3.1:8b   | Free, tool-calling capable, 8B fits RAM |
| STT             | OpenAI Whisper (base)   | Apache-2.0, runs on CPU                 |
| Sentiment       | HuggingFace DistilBERT  | Pre-downloaded at build time, no API key|
| Database        | SQLite (no CGO)         | Zero-install embedded, single file      |
| Real-time layer | gorilla/websocket        | Battle-tested, simple protocol          |

**MCP integration:**
The 7 tools exposed via MCP follow the Model Context Protocol standard. Any MCP-compatible AI assistant can connect and call `get_queue_status`, `route_call`, `flag_call`, etc. — making cortex-cc a **tool server**, not just a chatbot.
